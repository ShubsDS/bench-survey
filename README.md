# Benchmark audits

Adversarial validity audits of AI-control and misalignment evaluation datasets, environments and
benchmarks. The paper in this repo found that the standard APPS backdoor benchmark can be scored
on without finding sabotage: the classes have different authors, the test split's labels leak
through problem metadata, and many "working" backdoors are wrong only on inputs the problem
forbids. This directory runs the same kind of cheap checks on other benchmarks that people use to
rank monitors, set audit budgets and write safety cases.

It is self-contained so that it can become its own repository:

```bash
git subtree split --prefix benchmark-audits -b benchmark-audits
```

## Layout

| Path | What it holds |

| [`scope.md`](scope.md) | The first 15 benchmarks, the check suite (checks 0–7), the ranking and the disclosure plan |
| [`catalogue.md`](catalogue.md) | Further control and misalignment benchmarks found after the scope, in the same format |
| [`coverage.md`](coverage.md) | Every major benchmark covered so far, with its audit status and finding |

## Rules for every audit

- **Pin what was audited.** Record the dataset revision (Hugging Face commit or file hash) and the
  code commit. Each finding's script downloads from those pins.
- **Never run downloaded code.** Treat released solutions, trajectories and scorers as text unless
  the check needs them run, and then only in a sandbox. Run Python on downloaded data with `-I`.
- **State the flag rule before the run.** Each check in [`scope.md`](scope.md#2-the-check-suite)
  says in advance what result would change a published conclusion.
- **Report the bias direction.** Say whether the artifact makes the protocol look safer than it is
  (up) or less safe (down).
- **Respect the licence.** For data with no declared licence, publish aggregates and item ids only,
  never content.

## Telling maintainers

Nothing here is published until the maintainer and the authors whose conclusions it bears on have
had the note privately for 21 days, with an offer of a fix PR. The full plan is
[`scope.md` §4](scope.md#4-telling-maintainers-before-publishing).

## Running

```bash
pip install -r requirements.txt
```

Then follow the README in each `findings/` directory. Downloads go to a `data/` directory, which
the repository's `.gitignore` excludes.
